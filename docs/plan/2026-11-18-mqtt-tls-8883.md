# Plan: encrypted MQTT for sensors on port 8883 (option B)

Date: 2026-11-18. Branch: `deploy-aws`.

## Goal

Sensors connect to the AWS broker the way the smart-garbage group's ESP32 bins do: `mqtts://au-parking.duckdns.org:8883`, TLS with a Let's Encrypt certificate, login `sensor`. The ESP32 checks the certificate against ESP-IDF's built-in CA bundle, so no certificate file goes on the board, but it must connect by the DNS name, not the IP.

## Current state (facts this plan builds on)

- `docker-compose.prod.yml` runs Mosquitto with `mqtt/config/mosquitto.prod.conf`: one plain listener on 1883 (before this plan), `allow_anonymous false`, logins in `mqtt/config/pwfile`. Compose published 1883 at that point; the AWS security group kept it closed.
- The backend (`MqttConnection.java`) connects to `tcp://mosquitto:1883` inside the Docker network with `MQTT_USERNAME`/`MQTT_PASSWORD`. That traffic never leaves the server, so it stays plain.
- Caddy already holds a Let's Encrypt certificate for `au-parking.duckdns.org` and renews it by itself (around day 60 of 90). It keeps it in the `caddydata` volume under `/data/caddy/certificates/<issuer>/au-parking.duckdns.org/` (`.crt` with the full chain, `.key`). `<issuer>` is normally `acme-v02.api.letsencrypt.org-directory`, but Caddy can fall back to ZeroSSL.
- Mosquitto runs as uid 1883 and cannot read Caddy's files (root-owned key, other volume). Never run the dev `docker-compose.yml` on the server: it publishes an anonymous broker on 1883.
- Amazon Linux 2023 has no cron by default; it uses systemd timers.

## Step 1: Copy the certificate to the broker and keep it renewed

Add `deploy/sync-mqtt-cert.sh` and a systemd service + timer (`deploy/sync-mqtt-cert.service`, `deploy/sync-mqtt-cert.timer`). The script finds the newest certificate and key for the domain in the `caddydata` volume (any issuer folder) and copies them to the root-owned host folder `/etc/au-parking/mqtt-certs` as `server.crt` (mode 644) and `server.key` (mode 600), both owned by uid 1883. It restarts only the Mosquitto container when the certificate changed. It is safe to run any number of times and does nothing when nothing changed.

Safety rules in the script:

- It refuses a symlinked cert or key (the volume is written by the Caddy container).
- It refuses a cert and key that do not match (Mosquitto would not start at all), and keeps the old copy.
- A missing certificate exits non-zero with a clear message and does not delete the old copy.
- If the restart fails, a marker file makes the next run retry it.
- It needs `openssl` on the host.

Install on the server: the script as a root-owned copy (`sudo install -o root -g root -m 755 deploy/sync-mqtt-cert.sh /usr/local/sbin/sync-mqtt-cert.sh`), the unit files copied (not linked) into `/etc/systemd/system`, then `sudo systemctl daemon-reload`. The service runs `/usr/local/sbin/sync-mqtt-cert.sh` with `WorkingDirectory=/home/ec2-user/au-parking`. The timer runs **hourly**.

Acceptance: the script can be run against a temporary fake volume directory (the paths and restart command can be overridden): the first run copies and restarts, a second run with the same files does nothing; key is mode 600 owned by 1883; a missing, symlinked or mismatched cert exits non-zero without touching the existing copy.

Out of scope: changing Caddy or the HTTPS setup the app uses.

## Step 2: Add the encrypted listener on 8883

`mqtt/config/mosquitto.prod.conf` has two listeners. `listener 1883` stays inside Docker for the backend and is not published. `listener 8883` uses `/mosquitto/certs/server.crt` and `server.key`, TLS 1.2 minimum, and at most 50 connections. These settings are global, so they cover both listeners:

- `password_file` and `acl_file /mosquitto/config/aclfile`, `allow_anonymous false`
- `retain_available false` (a client that sets retain is disconnected)
- `max_packet_size 4096`, queue limits, `persistent_client_expiration 7d`

`mqtt/config/aclfile`: `parking-backend` may read `carcounter/#`; `sensor` may write only `carcounter/spots/#` and `carcounter/entrance/#`.

`docker-compose.prod.yml` publishes only 8883 and mounts `/etc/au-parking/mqtt-certs` read-only into Mosquitto at `/mosquitto/certs`. The certs are outside the repo, so there is nothing to gitignore. On the server, `aclfile` and `pwfile` must be `chown 1883:1883` and `chmod 600` (Mosquitto 2.1 warns now, future versions refuse otherwise).

If Mosquitto cannot load the certificate (missing or mismatched), it does not start at all, so the backend's internal 1883 is down too. It restart-loops until the certificate exists, so on the server the sync script must run before `up -d` (existing server) or right after Caddy gets its certificate (fresh server).

Acceptance: `docker compose -f docker-compose.prod.yml config` is valid with dummy secrets; with a self-signed test cert, a password publish over TLS on 8883 succeeds and an anonymous one is refused; 1883 is not published to the host.

Out of scope: backend code (it keeps using the internal 1883 listener); sensor firmware.

## Step 3: Document the deploy and the sensor connection

Update `docs/deploy-aws.md` (open 8883 in the security group, install the script and timer, run it once before starting Mosquitto (existing server) or after Caddy gets its certificate (fresh server), verify with `openssl s_client` and a TLS publish) and add `docs/sensor-connection.md` for the sensor team: broker URI, port, login (password shared privately), topics and exact JSON payloads, QoS 1, unique client id that is never `parking-backend`, connect by DNS name for the certificate check, and a troubleshooting table.

Acceptance: a teammate can follow `docs/deploy-aws.md` from a fresh server to a working TLS publish; `docs/sensor-connection.md` lists every value the firmware needs except the password.

Out of scope: sensor firmware code.

## Manual: done by hand on AWS (not for agents)

1. EC2 security group: add inbound **Custom TCP 8883, Anywhere-IPv4**. Leave 1883 closed.
2. Redeploy the changed files (compose, Mosquitto config, `aclfile`, `deploy/`), install the script and units, start the service once, then `docker compose -f docker-compose.prod.yml up -d`, then enable the timer. Full commands: `docs/deploy-aws.md`.
3. Check: `openssl s_client -connect au-parking.duckdns.org:8883 -servername au-parking.duckdns.org` shows a valid Let's Encrypt chain; a TLS publish with `--cafile /etc/pki/tls/certs/ca-bundle.crt` (Amazon Linux path) and `-u sensor` reaches the app.
4. Send the sensor team `docs/sensor-connection.md` and the `SENSOR_PASSWORD` privately.
